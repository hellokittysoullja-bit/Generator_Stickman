# Рилс 9:16 — как делать (плейбук, 22.10)

Собрано по ходу работы над рилсом эп.02 («Ещё пять минут»), по разбору ~190 роликов с YouTube
(пять волн расшифровок) и по правкам владельца. Правило: **что владелец похвалил — повторять, что отклонил — не возвращать.**

## Новый рилс с нуля — быстрый старт (для агента в новой сессии)
1. Прочитать этот файл целиком. Образец — **текущий эталон** из раздела «Эталоны» ниже: скопировать его reel.json в
   `videos/NN_тема/reel/reel.json` и переписать фразы, окна и звуки под свой эпизод.
2. **Правила проверяет код** (`scripts/reel_rules.py`, тесты `tests/test_reel_rules.py`): `reel.py` НЕ рендерит рилс,
   если хук длиннее 30 знаков, riser не с нулевой секунды, вторая фраза не на его пике, звук не из звуков владельца,
   есть музыка, картинка ниже 1400 px, план дольше 3 с, первая склейка позже 2 с, пик riser не на склейке, финал не
   на том же рисунке, что начало. `python scripts/reel_rules.py videos/NN/reel` — проверить без рендера.
   `--force` — только осознанно и с причиной в отчёте владельцу.
3. Одобренные значения стоят **по умолчанию** в коде (картинка 1420 px, `view_scale` 1.12, `fill_ink`, хук-субтитр
   с первого кадра, кипение линий, зерно, S-кривая, резкость, кукла на двойках) — их не надо вспоминать.
4. Чего код не проверит и что делает рилс хорошим, а не годным: **диссонанс первой фразы, звук по смыслу, выбор
   окна под каждое слово**. Это — разделы ниже; на этом владелец хвалил и правил.
5. Перед «готово» — раздел «Приёмка»; сравнить с рилсом эп.02 `scripts/reel_metrics.py` (не хуже по каждому числу).

## Эталоны (планка растёт)
Эталон — лучший рилс, одобренный владельцем, на сегодня. Не образец навсегда: следующий одобренный рилс, который
лучше (динамичнее, держит дольше, дороже), становится эталоном, а прежний остаётся в репозитории как история
(владелец 23.10: «старые будут как ностальгия»). Новый рилс сравнивается с ТЕКУЩИМ эталоном и не хуже его ни по одному
замеру `reel_metrics.py`. Сменить эталон — только словом владельца: дописать строку сюда и в скилл `reel`.
| с | рилс | что принёс |
|---|---|---|
| 22.10 (v10) **текущий** | `videos/02_sdvg_vremya/reel/` «Ты не ленишься» | хук-диссонанс, riser с 0 с, звуки по смыслу, картинка 74% экрана, правила кодом |

## Кто что делает
- **Рендер — скрипт** `scripts/reel.py` (камера, субтитры, звук, зерно, кукла, кодирование). Сам он ничего не придумывает.
- **Режиссура — руками Claude** в `videos/NN/reel/reel.json`: текст фраз, на каком слове какой план (окно кадрирования),
  где наезд, тряска, пометка от руки и **какой звук на каком слове**. Это и есть монтаж; скрипт только исполняет.
- Запуск: `python scripts/reel.py videos/NN/reel` (≈3 мин на 42 с), `--sheet` — лист всех кадрирований без рендера,
  `--preview` — 15 к/с. Новых платных картинок рилс не требует: берёт оплаченные кадры эпизода.

## Порядок работы
1. **Сценарий** — 12–17 фраз, ≈40 с, разговорно, на «ты», формы нейтральные по роду, без выдуманных цифр и медицинских
   обещаний («часто», «многим»). Каждое имя и термин — фактчек.
2. **Хук (первые 1–2 с решают всё, слово владельца):**
   - первая фраза бьёт в лоб **когнитивным диссонансом** по боли аудитории — людям с СДВГ **и** людям без диагноза
     с теми же симптомами: опровергает то, во что зритель про себя верит. Эп.02: «Ты не ленишься.» → «Ты не видишь время.»
     Не дольше ~1.3 с чтения (≤ ~25 знаков);
   - **текст хука стоит с первого кадра целиком**, без въезда и бледных слов (`still`, делается кодом для первой группы);
   - **в кадре с нулевой секунды движение**, которое значит то же, что текст (часы пролетают 23:55 → 03:12);
   - **riser с нулевой секунды**: `{"kind":"sfx","name":"riser","at":0,"align":"start","dt":-lead_in}`, его пик (1.65 с)
     — первая склейка: следующая фраза с `"after_sfx":"riser"`; план хука — наезд с разгоном (`"ease":"in"`) в эту склейку;
   - картинка, текст и звук хука значат одно (Kallaway: совпадение — 2 млн, рассинхрон — 50 тыс.);
   - хук не повторять дальше в сценарии (фраза «„Я просто ленюсь“? Нет» снята, когда её сказал хук).
3. **Структура (v6):** хук-диссонанс → бытовая сцена узнавания → авторитет по имени (Баркли, «слепота ко времени») →
   «и без диагноза тоже» → открытая петля («что помогает — покажу») → контраст → «но вот ловушка» → провал (смешной) →
   решение по имени (боди-даблинг) → твист (нарисованный кот) → продукт → призыв → финал = начало (петля).
4. **Кадрирования** — окна `[cx, cy, h]` в пикселях ИСХОДНОГО кадра; проверять листом `--sheet` глазами, не по рамкам судьи
   (они бывают мимо). Пустой предмет (циферблат без стрелок) годится, только если он и есть смысл фразы.
5. **Звуки по смыслу** (см. ниже), рендер, проверка (см. «Приёмка»), коммит.

## Звук — только звуки владельца, и только по смыслу
**Библиотека — `assets/sfx/reels/library.json`:** у каждого звука описание (как звучит, что значит, когда ставить,
когда НЕ ставить, где пик, замеры) — слушать файл не нужно, `reel.py` берёт звуки оттуда. Новый звук владельца =
файл в папку + запись в library.json со всеми полями (тест это проверяет); без записи звук не пройдёт правила.
Похвала владельца 22.10: «звуки по смыслу» — `oof` ровно на «…и продолжаешь», где кот
провалил таймер. Так и ставить: **звук озвучивает событие картинки или поворот смысла, а не украшает склейку.**
| звук | когда | как |
|---|---|---|
| `riser` (Metallic Riser) | интрига, в КАЖДОМ рилсе, с нулевой секунды | пик на первой склейке (`after_sfx`) |
| `swoosh` | хлёсткая склейка (`whip`) | пиком в первый кадр нового плана (J-cut звука) |
| `swoosh_deep` | влёт важного предмета или кота | на слове появления |
| `oof` | смешной провал, «ну вот опять» | на слове провала |
| тихий `swoosh` −7 дБ | наезд на ключевое слово, вход наездом | ставится кодом, если в 1 с нет другого звука |
- **Никаких звуков на субтитрах** (решение владельца). Один звук — одно событие, не стопкой. Края 10 мс.
- **Музыки нет** (решение владельца 22.10, «музыку не надо») — не предлагать и не подкладывать. Звук рилса — только звуки по смыслу.
- Чужие звуки (тиканье, «дзынь», щелчки) — только с разрешения владельца.
- С озвучкой (`alignment.json`) все звуки на 7 дБ тише.

## Субтитры (одобрены владельцем)
- Onest Black (OFL), 90 px, регистр предложения, **одна строка, один кегль, одна базовая линия на весь ролик**;
  не влезает — группа делится, а не уменьшается. 1–3 слова в группе, без точек и запятых, предлог не висит в конце.
- Белые буквы, обводка 6 px, мягкая тень; активное слово жёлтое, ключевое (`*слово*`) оранжевое, когда до него дошло
  чтение; ещё не прочитанные слова бледные (кроме хука).
- Не быстрее 17 знаков в секунду, не короче 0.5 с; въезд снизу 18 px за 0.25 с без перелёта.
- **Субтитр никогда не ложится на рисунок** — своя полоса под картинкой. Бионический шрифт — отклонён.

## Раскладка экрана 1080×1920
- **Картинка 0–1420 (74%), полоса субтитров 1420–1570, внизу 350 px** под подпись и кнопки Instagram
  (`"picture_h": 1420` в reel.json). Владелец 22.10: «столько воздуха в рилсах не оставляют» — при 1100 низ был
  пустой половиной экрана. Разбор 31 ролика: пустым низ не оставляет никто, интерфейс закрывает нижние 350–400 px.
- `"fill_ink": true` — окно не уходит ниже последней линии рисунка (иначе пустая бумага переезжает внутрь картинки).
- Верхние 14% — без ключевого текста (шапка Reels): часы хука на 27% высоты картинки.
- Экранные координаты в reel.json (`cy`/`h` у `fit`/`doll`, `y` пометок) пишутся под 1100 и пересчитываются кодом.

## Монтаж
- Склейка на начало слова за 2 кадра; план 0.7–3 с, в зоне хука ≤ 2 с; неподвижных кадров нет (дрейф постоянной
  скорости + поворот до 0.5°, «кипение» линий 12 раз в секунду, зерно).
- Наезд (`punch`) на ключевом слове, тряска на ударе, хлёст (`whip`) на смене места, вход наездом (`zoom_in`) с гаснущим
  размытием, прожектор (`spot`) на главном предмете, красный круг от руки (`circle`), слово от руки с маркером (`mark`).
- Рукописные пометки приклеены к бумаге (едут с камерой). Кукла кота «на двойках» (12 к/с). Конец = начало.

## Приёмка (перед «готово»)
1. `--sheet` — все кадрирования глазами: нет обрезков (полглаза кота у края), нет пустой бумаги вместо смысла.
2. Кадры в 0.0 / 1.0 / 1.65 / 2.5 с: хук читается в первом кадре, часы не режутся краями, склейка на пике riser.
3. Замеры по готовому файлу: доля неподвижных кадров, самый длинный план (≤ 3 с), доля тишины, первая склейка
   (≤ 2 с): `python scripts/reel_metrics.py old.mp4 new.mp4` — версии сравниваются одним прибором.
4. Честно назвать, что не проверено: телефон глазами владельца, удержание после публикации.
- Резкость: кипение линий только в том же проходе выборки, что и камера (второй проход мылил рисунок на 11%).

## Проверить в следующих рилсах (волна 6, 23.10 — идеи с источником, не правила)
- Вторая или третья фраза снимает возражение: «и без диагноза тоже» ближе к хуку (Kallaway, средняя сила).
- Короткий план-реакция кота после факта; после плотного куска — общий план-передышка (HillierSmith, Matt Loui).
- Направление движения и место главного предмета на экране сохраняются через склейку (Tim Runia, 729 тыс.).
- Призыв — за ≥ 5 с до конца, с конкретным подарком (The Tutorial Girl: 1500 подписчиков Telegram с одного ролика).
- Хук «Ты не…» в каждом рилсе станет кликбейтом (The Futur) — менять тип хука от рилса к рилсу.

## Открытые вопросы владельцу (на 23.10)
- Кот-напарник живьём внизу кадра весь ролик (боди-даблинг прямо во время просмотра) — показан листом, не решено.
- Призыв на пересылку «Отправь тому, кто думает, что ты ленишься» (доказательства сильнее всех: пересылки — сигнал
  платформы), обработка повторов своих звуков (высота ±5–15%, панорама), слово-ключ в комментарий (нужна автоматическая рассылка), единый акцентный цвет.

## Откуда правила (доказательства, кратко)
Разобрано 189 роликов (`docs/reels_sources.txt` — список ID, не изучать повторно), плюс правки владельца.
- **Первые секунды:** у вирусных шортсов остаются после первых секунд 70–90% зрителей, при < 40% — меньше 10 тыс.
  просмотров (Galloway, 5 500 шортсов, корреляция); ни одного вирусного ниже 65% (Nick Edward); цель 80/80 (Стас Маар).
- **Хук:** картинка, текст и звук значат одно (Kallaway: 2 млн против 50 тыс.); текст хука с первого кадра без
  анимации (heyDominik), понятен без звука (Jenny Hoyos, moneyboymax); хук-понятие и хук-ситуация про прокрастинацию
  (Тимочко: 2.7–5 млн, пролистывают 17–18%); 5–12 слов, с отрицанием («не»).
- **Riser:** сам по себе не хук, а ожидание перед раскрытием (Clumzzy) — поэтому пик на первой склейке; начало
  «только на музыке» работает плохо (FluxNote, 500 роликов).
- **Звук:** один звук — одно событие; бумажный визуал — бумажный звук (Старый Спорт); звук озвучивает действие.
- **Экран:** интерфейс Shorts/TikTok закрывает нижние 350–400 px (Restream), пустым низ не оставляет никто.
- **Субтитры:** ≤ 17 знаков в секунду (StudioBinder), одна строка, одно место, слово-за-словом.
- **Ритм:** смена картинки каждые 2–3 с; неровный ритм прерываний, плотнее в начале (BAZA_KORMIT); петля даёт
  удержание выше 100% (Стас Маар).
- **Пересылки** — один из главных сигналов Instagram (глава Instagram Моссери, через Jade Beason); порядок сигналов:
  досмотр первых 3 с → досмотр и пересмотр → пересылки → комментарии → сохранения → лайки (Ar2r Hart). СДВГ-авторы:
  пересылают, чтобы показать «это не только я» (How to ADHD с Dani Donovan, Catieosaurus, Elyse Myers).
- **После хука — «зона закрепления»** (Kallaway): 1–3 фразы, которые снимают возражение или называют понятие.
- **Звук:** «акцент на всём = акцент ни на чём», звук озвучивает и мысль, и движение камеры (Film Editing Pro, 1.1 млн);
  повтор одного свиста заметен — его меняют по высоте ±5–15% и панорамой (Gaku Lange, Marketing Demons).
- **Не доказано и названо как мнение:** «дорогой» вид (зерно, S-кривая) — мнения практиков; против — «смысл важнее
  красоты» (3_rL, Сенаторов). Немые рилсы с одними субтитрами прямо не мерил никто — проверка только публикацией.

## Исследование YouTube
Расшифровки — `yt-dlp --skip-download --write-auto-subs`, `player_client` ios/android/web_embedded, языки
en-orig/ru-orig/hi-orig, паузы между запросами (иначе проверка на бота). Поиск — YouTube Data API (ключ у владельца,
в репозиторий не класть); у проекта ключа отдельный суточный лимит «Search Queries per day» кончается за несколько
запросов, сброс в полночь по Тихоокеанскому времени — тогда искать через `yt-dlp "ytsearch20:запрос"`.
Каждую расшифровку читать целиком. Уже изученные ID — `docs/reels_sources.txt` (дописывать после каждой волны); не повторять.
